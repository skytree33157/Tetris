네트워크 다인전 UI 구현 가이드
==============================

이 문서는 네트워크 다인전(P2P) 화면을 구현하거나 수정하는 사람을 위한 참고 자료입니다.
기준 코드: src/main/java/network, src/main/java/menu, src/main/java/game


1. 실행 진입점
--------------
현재 다인전은 시작 메뉴가 아니라 명령줄 인자로만 시작합니다.

  빌드:    .\gradlew.bat classes          (반드시 프로젝트 루트에서 실행)
  호스트:  java -cp "build\classes\java\main;build\resources\main" app.Main --p2p-server NORMAL
  클라이언트: java -cp "build\classes\java\main;build\resources\main" app.Main --p2p-client localhost

- --p2p-server <NORMAL|ITEM>: 방 생성. 게임 모드를 인자로 받습니다.
- --p2p-client <주소>: 방 참여. 호스트 주소를 입력합니다.
- 기본 포트: P2PMatchSession.DEFAULT_PORT = 57823
- 시작 메뉴(StartMenu.MENU_ITEMS)에는 다인전 항목이 없습니다. UI에서 진입 버튼을 추가하려면
  P2PGameRunner.startServer(mode) / P2PGameRunner.joinServer(address)를 호출하면 됩니다.


2. 화면 흐름
------------
  [진입 인자 또는 메뉴]
        |
        v
  P2PGameRunner.startServer / joinServer   (백그라운드 스레드에서 세션 생성)
        |  성공 시 SwingUtilities.invokeLater로
        v
  P2PMatchRunnerLoop.showLobby()
        |-- GameScreen 생성 (숨김 상태로 미리 준비)
        |-- P2PLobbyScreen 표시 (대기실)
        |        호스트: "대전 시작" 버튼 (참가자 2명 이상일 때 활성화)
        |        클라이언트: 시작 버튼 없음, 대기만 함
        v
  onStarted 콜백 -> 대기실 닫기, GameScreen 표시, allowGameStart()
        |
        v
  대전 진행 (GameScreen)
        |-- 상태 주기 전송, 공격 송수신, 연결 지연 표시
        v
  onResult 콜백 -> GameScreen.showMatchResult(ranking, mySlot) -> 세션 종료

  연결 끊김(onDisconnected) -> 화면 정리 후 에러 메시지 -> StartMenu 복귀

대기실에서 "나가기"를 누르면 세션을 닫고 StartMenu로 돌아갑니다.


3. 주요 클래스와 역할
--------------------
- P2PMatchSession (network)
  호스트와 클라이언트의 소켓, 메시지 송수신, 매치 규칙을 담당합니다.
  UI는 이 클래스의 공개 메서드만 호출하고, 콜백은 Listener 인터페이스로 받습니다.

- P2PGameRunner (menu)
  세션과 화면을 연결합니다. 내부 클래스 P2PMatchRunnerLoop가 대기실 -> 대전 -> 결과 흐름을 관리합니다.

- P2PLobbyScreen (menu)
  대기실 화면. updateRoster(slots, mySlot)으로 참가자 목록을 갱신합니다.

- P2PGameController (menu, MatchLink 구현)
  GameScreen의 ActionController와 세션을 잇는 어댑터입니다.
  attach(): ActionController에 자신을 연결합니다.
  publishAttack(rows): 공격 행을 세션에 전달합니다.
  reportGameOver(): 개인 게임 오버를 상대에게 알립니다.
  sendGameStatus(): 현재 점수, 레벨, 줄 수를 주기적으로 보냅니다.

- MatchLink (game)
  ActionController가 다인전 경기에 접근하는 인터페이스입니다.
  isRunning(), publishAttack(rows), reportGameOver()

- GameScreen (menu)
  다인전에서 추가된 public 메서드:
  setP2PController(controller)   : 컨트롤러 연결
  allowGameStart()               : 시작 신호 후 게임 루프 시작 허용
  showMatchStatus(text)          : 사이드 패널의 매치 상태 문구 변경 (기본 문구 없음)
  showMatchResult(ranking, slot) : 최종 순위 표시 후 결과 처리
  showConnectionStatus(msg, warn): 연결 지연 문구 표시 (노란색 라벨)
  hideConnectionStatus()         : 연결 지연 문구 숨김
  stopGame(), getActionController(), getScoreManager(), getGameStateManager()


4. Listener 콜백 (P2PMatchSession.Listener)
-------------------------------------------
  onRosterChanged(List<Integer> slots)  참가자 목록 변경. 대기실 갱신에 사용합니다.
  onStarted()                           호스트가 대전을 시작했습니다.
  onRemoteStatus(slot, GameStatus)      상대 상태 수신. 게임 화면 사이드 패널의 상대 점수판(OpponentStatusPanel)에 표시합니다.
  onAttack(List<int[]> rows)            공격 행 수신. ActionController.receiveAttackRows로 전달합니다.
  onResult(List<Integer> ranking)       대전 종료. ranking[0]이 1등입니다.
  onDisconnected(IOException)           연결 끊김.
  onConnectionLatency(int slot)         상대(슬롯)로부터 3초 동안 메시지가 없음. 지연 경고를 표시합니다.
  onConnectionRecovered(int slot)       지연 상태였던 상대가 복구됨. 경고 목록에서 제거합니다.

스레드 규칙
- 콜백은 네트워크 스레드에서 호출됩니다. Swing 컴포넌트는 반드시 SwingUtilities.invokeLater로 갱신합니다.
- 예외: onAttack은 네트워크 스레드에서 직접 ActionController.receiveAttackRows를 호출합니다.
  (ActionController의 stateLock으로 보호됩니다.)


5. 매치 규칙 (UI 문구를 정할 때 참고)
-----------------------------------
- 참가 인원: 최소 2명, 최대 10명 (MIN_PLAYERS_TO_START, MAX_PLAYERS)
- 제한 시간: 180초 (MATCH_TIME_LIMIT_MS). 시간이 끝나면 점수 순으로 순위를 매깁니다.
- 공격: 한 블록으로 2줄 이상 지웠을 때만 발생합니다. 1줄 삭제는 공격이 없습니다.
- 공격 대상: 호스트가 살아 있는 상대 중 무작위로 고릅니다. 보낸 사람과 게임 오버한 플레이어는 제외합니다.
- 공격 적용: 받은 즉시 보드에 행이 추가되고, 떨어지던 블록이 같은 칸 수만큼 올라갑니다.
  일시정지 중이거나 줄 삭제 연출 중이면 대기열에 있다가 재개 후 적용됩니다.
  대기열은 최대 10개(ActionController.MAX_PENDING_ATTACK_ROWS)입니다.
- 순위: 생존자가 먼저, 탈락자는 나중에 탈락한 순서대로 정합니다.
- 게임 오버 후에도 결과가 확정될 때까지 게임 화면은 "GAME OVER - 대기 중" 상태로 남습니다.


6. 연결 상태와 오류 처리
-----------------------
- ConnectionMonitor: 3초 동안 메시지가 없으면 지연, 10초 동안 없으면 끊김으로 판단합니다.
- 연결 지연은 게임 화면에만 표시합니다. 대기실에는 표시하지 않습니다.
- 지연 중인 상대는 LatencyStatusTracker(슬롯 집합, P2PGameRunner가 사용)로 관리합니다. 라벨에는 "P2, P3 연결 지연 중..."처럼 표시하고,
  집합이 비면 라벨을 숨깁니다. 상대가 나가 onRosterChanged로 로스터에서 빠지면 집합에서도 제거합니다.
  (슬롯 표시 이름은 대기실과 같이 "P" + (슬롯 + 1)입니다.)
- 클라이언트 연결 끊김: 게임 화면을 닫고 에러 메시지를 띄운 뒤 StartMenu로 돌아갑니다.
- 호스트에서 클라이언트가 끊기면: 에러 화면 없이 해당 플레이어를 탈락 처리하고 게임을 계속합니다.
- 연결 실패(접속 불가 등): showConnectionFailure가 에러 메시지를 띄우고 StartMenu로 돌아갑니다.


7. 알려진 제한 사항 (UI 작업 전 확인)
------------------------------------
- 시작 메뉴에 다인전 진입 버튼이 없습니다. 명령줄 인자로만 실행할 수 있습니다.
- 대기실에 연결 지연 표시가 없습니다.
- 호스트 쪽 끊김 처리가 클라이언트와 다릅니다 (위 6번 참고).
- 상대 점수판은 점수/레벨/라인/탈락 여부만 표시합니다. 상대 보드는 전송되지 않아 표시하지 않습니다. 보드까지 보이려면 새 메시지 타입이 필요합니다.


8. 테스트
---------
관련 테스트는 다음 명령으로 실행합니다.

  .\gradlew.bat test --tests "game.*" --tests "network.*" --tests "board.*"

- 네트워크 세션 테스트: src/test/java/network/P2PMatchSessionTest.java
- 공격 적용 테스트: src/test/java/game/BattleAttackTest.java
- 실제 두 개 이상의 창에서 수동 테스트는 아직 수행하지 않았습니다.
