# 네트워크 대전 화면 지연 측정

네트워크 대전(P2P)에서 한쪽의 조작이 상대 화면에 200ms 이하로 표시되는지 확인하는 방법입니다.
측정 도구는 [LatencyProbe.java](../src/test/java/network/LatencyProbe.java)이며, 게임과 별도로 실행되는 독립 프로그램입니다.

## 측정 원리

- 게임은 상태를 50ms마다 상대에게 보내고, 수신 측은 다음 렌더 프레임에 화면을 갱신합니다.
- 도구는 게임과 같은 TCP 설정(`TcpNoDelay`)으로 50ms 간격의 에코 왕복을 측정합니다.
- 편도 지연은 왕복 시간의 절반(RTT/2)으로 계산합니다.
- 화면 표시 지연 예상치 = 편도 지연 p99 + 50ms(상태 송신 주기) + 16ms(한 프레임)
- 예상치가 200ms 이하이면 `결과: 통과`, 초과하면 `결과: 실패`를 출력합니다.

## 준비

- 두 PC가 같은 공유기(같은 Wi-Fi 또는 랜선)에 연결되어 있어야 합니다.
- 서버 PC의 방화벽에서 사용할 포트(예: 7777)의 접속을 허용해야 합니다.
- 이 저장소를 빌드한 PC라면 추가 준비가 필요 없습니다.

```
.\gradlew.bat compileTestJava --offline
```

- 다른 PC에서 실행하려면 `build\classes\java\test\network\LatencyProbe*.class` 파일을 복사하세요. 게임 코드에 의존하지 않으므로 이 파일만으로 실행됩니다.

## 실행 방법

1. 서버 PC에서 먼저 실행합니다. 이 창은 측정이 끝날 때까지 닫지 마세요.

   ```
   java -cp build\classes\java\test network.LatencyProbe server 7777
   ```

   `대기 중: 포트 7777`이 출력되면 준비된 것입니다.

2. 서버 PC의 IP 주소를 확인합니다. 서버 PC에서 `ipconfig`를 실행하고 "IPv4 주소"를 찾습니다.

3. 클라이언트 PC에서 실행합니다. `192.168.x.x`는 2번에서 확인한 IP로 바꾸고, 마지막 숫자는 측정 시간(초)입니다.

   ```
   java -cp build\classes\java\test network.LatencyProbe client 192.168.x.x 7777 30
   ```

4. 측정이 끝나면 클라이언트 PC에 결과가 출력됩니다.

## 결과 읽는 법

```
샘플 N개 (편도 지연 추정, RTT/2)
  최소 a ms / 평균 b ms / p95 c ms / p99 d ms / 최대 e ms
화면 표시 지연 예상 (p99 기준): f ms
결과: 통과 (200ms 이하)
```

- 샘플 수는 측정 시간과 50ms 간격에 따라 대략 `측정 초 × 20`개가 나옵니다.
- 판정은 p99 기준입니다. 평균이 낮아도 p99가 높으면 실패로 판정될 수 있습니다.

## 문제 해결

- `Address already in use`: 같은 포트를 쓰는 이전 서버가 남아 있습니다. `Get-NetTCPConnection -LocalPort 7777`로 PID를 찾아 `Stop-Process -Id <PID>`로 종료하세요.
- `응답이 하나도 없습니다`: IP, 방화벽, 포트, 두 PC의 네트워크 연결을 확인하세요.

## 한계

- 이 도구는 게임 소켓 경로가 아니라 같은 설정의 에코 경로를 측정합니다. 게임 내부의 입력 처리와 렌더링 시간은 포함하지 않습니다.
- 편도 지연을 RTT/2로 추정하므로 송수신 경로가 대칭이라고 가정합니다. 유선 LAN에서는 대체로 맞지만 무선에서는 차이가 날 수 있습니다.
- 실제 게임 화면 기준의 지연을 정확히 재려면 게임 메시지에 타임스탬프를 넣어야 하며, 이는 프로토콜 변경이 필요합니다.
